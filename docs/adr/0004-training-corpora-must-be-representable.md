# Training corpora must survive encoding into their target

`train.py` encodes each language corpus into every registry-declared target encoding with `errors="ignore"`, and until now shipped whatever came out as long as at least 10 bytes survived. For `sr/cp1250` that produced a degenerate model: the CulturaX Serbian corpus is Cyrillic, which cannot encode into cp1250, so nearly every letter was silently dropped and the model was trained on the leftover spaces, punctuation, and digits (119 bigram entries, weight 255 on the space-space bigram). Compounding it, whitespace collapsing ran *before* encoding, so the dropped letters created fresh space runs that became the model's dominant "signal." Any space-padded input then cosine-matched Serbian at up to 0.93 confidence. `ur/cp1006` had the same disease in a milder form (incomplete Arabic presentation-form substitutions), and `fa/iso8859-6` in miniature.

Three rules now apply, decided for the 7.6 retrain:

1. **Whitespace collapses after substitution and encoding**, not before, so character loss can never manufacture whitespace bigrams.
2. **A retention guard hard-fails the training run** when a (language, encoding) pair's corpus mostly fails to encode. The registry's language list on an encoding is a claim that the pair is representable; failing the guard means either the registry claim is wrong or the preprocessing (substitutions, transliteration) is incomplete. Both are bugs to fix, not conditions to ship around. Skip-and-warn was rejected because it ships a silent coverage gap, which is exactly how the degenerate model got out the first time.
3. **When the corpus script doesn't match a target encoding's script, fix the corpus deterministically.** Serbian is digraphic, so the Cyrillic corpus is transliterated to Gaj's Latin alphabet at training time for Latin-script targets. Rejected alternatives: filtering the corpus to its few Latin-script articles (sample count collapses), sourcing the Serbo-Croatian `sh` corpus (blends three languages that `hr/cp1250` already covers), and dropping the model (Serbian-Latin text would detect fine via hr, but with the wrong language label).

Resist softening the hard-fail to a warning the first time it makes a retrain inconvenient; the inconvenience is the guard working. If a pairing genuinely cannot be made representable, the fix is removing the language from that encoding's registry entry, not teaching the trainer to shrug.
